# PR-Agent: автоматическое ревью pull request'ов

Workflow [`.github/workflows/pr-agent.yml`](../.github/workflows/pr-agent.yml) поднимает
контейнер [PR-Agent](https://docs.pr-agent.ai/) на каждый PR и публикует ревью
комментарием. Отдельного сервиса, домена и webhook'а нет — только GitHub Actions.

Настройки PR-Agent приходят **только переменными окружения**: файл `.pr_agent.toml` в
репозиторий не кладётся. PR-Agent читает его из проверяемой ветки, то есть из кода самого
PR, — а в job'е лежат ключ шлюза и токен GitHub. По той же причине workflow не делает
checkout: дифф PR-Agent забирает по API.

## Что нужно один раз

Секреты репозитория: `Settings → Secrets and variables → Actions`:

| Секрет | Значение |
| --- | --- |
| `OPENAI_API_BASE` | OpenAI-совместимый адрес шлюза **вместе с `/v1`**: `https://openrusrouter.ru/v1` |
| `OPENAI_KEY` | ключ шлюза |
| `PR_AGENT_TOKEN` | необязательный PAT, если ревью должен писать бот-пользователь; иначе берётся штатный `GITHUB_TOKEN` |

Проверка после добавления: `Actions → PR-Agent → Run workflow`. В job'е `doctor` будут
`Preflight` (хост, DNS, `TCP: соединение установлено`, `HTTP: 200`) и три галочки
проверок — модель сконфигурирована, ключ найден, запрос к модели проходит.

## Режимы

- **review** — на `opened`, `reopened`, `ready_for_review`. `synchronize` выключен
  намеренно: иначе PR из десяти коммитов — десять платных ревью. Нужно ревью на новый
  пуш — `/review` в комментарии.
- **command** — комментарий, первая строка которого начинается со слэша:
  `/review`, `/describe`, `/improve`, `/improve --extended`, `/ask <вопрос>`,
  `/add_docs`, `/update_changelog`, `/generate_labels`.
- **doctor** — ручной запуск, проверка секретов и доступности шлюза.

Команды разрешены **только владельцу репозитория** (`--allowed-users` не задан):
право комментировать PR не должно давать право запускать команды, потому что тело
комментария становится аргументами `pr-agent`, а job держит ключ и токен.

## Грабли, уже учтённые

- адрес в `OPENAI_API_BASE` — ровно `https://openrusrouter.ru/v1`: домена `.ai` не
  существует, опечатка в домене выглядит как `Connection error` без подробностей;
- `CONFIG__MODEL` — `openai/deepseek/deepseek-v4.1-flash-1017`: LiteLLM отрезает
  префикс `openai/` и отправляет остаток как есть, поэтому id со слэшем пишется целиком;
- `CONFIG__REASONING_EFFORT=none` плюс id в `ADDITIONAL_REASONING_EFFORT_MODELS`:
  иначе модель рассуждает, выжигает бюджет ответа и возвращает пустой `content`;
- `CONFIG__FALLBACK_MODELS=[]`: умолчание подставляет посторонние модели и маскирует
  настоящую причину отказа;
- образ закреплён по тегу (`pragent/pr-agent:0.50.0`), а не `:latest`: прогоны должны
  быть сравнимы между собой.

## Ограничения

- PR из форков не ревьюятся: job получает секреты и отправляет дифф на внешний шлюз, а
  ветку из чужого репозитория контролирует автор PR;
- образ тянется с Docker Hub — при лимитах на анонимные pull'ы его стоит положить в
  собственный реестр и переключить `PR_AGENT_IMAGE`;
- Gitea-путь (`.gitea/workflows/`) этим workflow не затрагивается: здесь описан GitHub
  Actions.
